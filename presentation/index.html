What is this?

  • A playable Quake 1 single-player & deathmatch level…
  • …that recreates a real place: Loyola's campus bridge over Charles Street, the 1896 Knott Hall, and the Seton & Hopkins Court dorms on west campus.
  • Every brush, light, and spawn point is emitted by Python code (written with AI assistance) — no hand-editing in an editor.
  • An exploration of what AI can do, and working to understand the code it writes along the way.

The workflow

How is this done?

  • Mostly prompting — describing geometry in plain language and letting the AI emit the Python.
  • Reference photos in ref/ — real shots of the bridge, hall & dorms guide proportions and detail — alongside screenshots from a Quake map I built in the 90s whose source code is long lost.
  • TrenchBroom round-trips — open loyola.map, eyeball or tweak geometry, then fold changes back into the Python.
  • Quake's viewpos — print the player's coordinates in-game to capture exact spots for spawns, teleports & props.

The real place

  • Loyola's Evergreen campus, north Baltimore (39°20′46″N, 76°37′08″W)
  • A Collegiate-Gothic arched stone bridge spans North Charles Street, linking west & east campus.
  • Knott Hall — the oldest building on campus — sits just to the east.
  • Seton & Hopkins Court — the west-campus dorms — anchor the other end of the bridge.
  • The map even reproduces the carved “LOYOLA UNIVERSITY MARYLAND” parapet lettering — visible on the real bridge behind.

The twist

Python — no manual brushwork

One command assembles the whole world and writes a Quake .map file:


python3 generate_map.py      # → loyola.map
# or simply:
just generate

Each area module contributes geometry; the builder serialises it to the text-based .map format Quake compilers understand. The code itself was written with AI assistance.

Open it in TrenchBroom

  • The generated loyola.map loads straight into TrenchBroom — brushes, entities & textures all editable by hand.
  • Great for eyeballing geometry, checking spawns, and spotting leaks the compiler would flag.
  • In some cases we've back-ported edits — tweak a brush in TrenchBroom, then fold the change back into the Python so the source stays the single source of truth.
  • Round-trips cleanly: Python → .map  → TrenchBroom → Python.

The data model

Three dataclasses in quake_loyola.mapdata describe everything:

Face

Three coplanar points define a half-space, plus a texture & alignment.

Brush

An ordered list of faces bounding one convex solid.

Entity

A classname + key/values, optionally with brushes (e.g. func_detail).

MapBuilder collects world brushes & entities, then to_map() serialises the scene.

The MapBuilder

Each area module hands its brushes & entities to one collector; to_map() serialises the whole scene.


class MapBuilder:
    """Accumulates world brushes and entities, then serializes a .map document."""

    def __init__(self):
        self.brushes = []   # worldspawn geometry
        self.entities = []  # point + brush entities

    def add_brushes(self, brushes):  self.brushes.extend(brushes)
    def add_entities(self, entities): self.entities.extend(entities)

    def to_map(self, worldspawn_fields) -> str:
        world = Entity("worldspawn", dict(worldspawn_fields), self.brushes)
        blocks = [world.to_map()] + [e.to_map() for e in self.entities]
        return "\n\n".join(blocks) + "\n"

Geometry primitives

Shape constructors in quake_loyola.geometry return brushes:

  • box(...) — axis-aligned prism
  • ramp_slab(...) — sloped wedge (X / Y)
  • pyramid(...) — gable roofs & caps
  • arch_seg(...) — one voussoir of an arch
  • arch_wall(...) — a full arched pier
  • layered_wall(...) — multi-storey wall w/ openings

# The arched bridge deck follows a parabola:
def deck_top_z(x):
    return BRIDGE_DZ2 + arch_z_at(x)   # crown rises BRIDGE_ARCH_RISE (144u)

Naming conventions

Constants read as <AREA>_<FEATURE>_<SUFFIX> — once you know the vocabulary, names self-describe.

Axis / size

X1/X2 box min/max · CX/CY centre · DZ1/DZ2 deck Z · H/HW height/half-width · T/R/D thickness/radius/depth

Features

PILLAR · BLK · PYR · WIN · ENT · DRIVEWAY_WS/RD/ES (W→E) · KH Knott Hall

Example: BRIDGE_PILLAR_CAP_OVH = bridge pillar cap overhang. Full legend lives in constants.py & the docs.

Understanding the code

  • Procedural at heart — the world is built by functions that emit geometry, not a tree of objects. Each module's build() returns plain (brushes, entities).
  • OOP where it earns its keep — @dataclass Face / Brush / Entity model the .map format; MapBuilder collects & serialises it.
  • Spec dataclasses — BridgeSpec, KnottSpec, DormSpec, LightingPreset bundle related constants into one tidy value.
  • Generators — yield walks floors, arch voussoirs & window rows lazily instead of building big lists.
  • Pure modules — no I/O or globals; geometry in, geometry out, so everything is testable & deterministic.
  • One source of truth — every dimension lives in constants.py, which keeps the math honest.

Quake brushes are inherently data — so a functional, data-first style fits better than deep class hierarchies.

Room to grow

What could make this even better?

  • Tighter real-world accuracy — proportions still lean on eyeballed reference photos.
  • Automated reference gathering — imagine Claude driving Playwright to browse Google Maps, pull Street View angles & measurements, and feed them straight into the geometry.
  • Static type checking — most geometry functions are still untyped; adding type hints + mypy (e.g. a Vec3 alias, -> list[Brush] returns) would catch argument-order & unit bugs in CI instead of after the fact.
  • Realistic trees — the current foliage is crude; proper models or denser func detail would make the campus greenery far more convincing.
  • Less manual round-tripping — close the loop so TrenchBroom tweaks & viewpos captures flow back into the Python automatically.
